# Tree Page v2 ("The Botanical Record") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/plants/:id` around the six owner questions, with year-on-year comparison, milestones, a year-grouped and filterable record, and an in-app memory card. Two small backend changes support it: timeline `types` filtering and season-total yield.

**Architecture:**
- The backend gains an optional `types` query on the timeline and sums harvest yield per cycle.
- The web keeps the data logic in pure functions inside `features/biography`, each with its own unit tests. `PlantDetailScreen` composes focused section components.
- Features import each other only through `index.ts`.

**Tech Stack:** NestJS 11 + Prisma 6 (jest, supertest e2e); React 19 + Vite + TanStack Query 5 + zod 4 + Tailwind 4 (Vitest + MSW, Playwright).

**Spec:** `docs/superpowers/specs/2026-11-10-tree-page-v2-design.md`

## Global Constraints

- No made-up numbers: a missing value renders "—" with no marker; vitality, points and push are placeholders with `TODO(<name>)` comments and no UI.
- No client-side filtering of paged timeline data; the filter goes to the server as `types=A,B`.
- IST for every "year" and "this month" decision (`web/src/lib/ist.ts`).
- All copy in `web/src/locales/en.json`. No `console.*` and no `throw new Error` (enforced by `check:boundaries`).
- Every data section has loading, error-with-retry and empty states.
- TDD: write each test first, watch it fail, then implement.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A plant with no planting date (`precision: UNKNOWN`) should get no age line, a muted "Planted" milestone and no memory card. Not "0 years" and not a crash. (Task 4 `plantAge`/`memoryFor` tests; Task 5 render test.)
2. A filter with no matches should show "No moments of this kind yet", not the never-logged empty state, and keep the filter chips visible. (Task 5.)
3. Old harvest entries carry `metadata.quantity` as a string ("3 kg") instead of `quantity_value`/`quantity_unit`. They should still get a tag. (Task 4 `entryTags` test.)
4. Cycles with yields in mixed units should bar only the latest unit, and show the other years as text. (Task 4 `yearOnYear` test.)
5. An entry at 31 Dec 20:00 UTC is 1 Jan in IST, so it groups under the new year. (Task 4 `groupByYear` test.)

### Task 4: Web — pure record logic

**Files (all in `web/src/features/biography/`):**
- Create: `plant-age.ts`, `year-on-year.ts`, `record-timeline.ts` and `memory.ts`, each with a `*.test.ts` beside it.

**Interfaces:**
- Produces:
  - `plantAge(plantingDate: string | null, precision: Plant['planting_date_precision'], now: Date): { unit: 'years' | 'months'; count: number; year: number } | null`. This is `null` without a date or for UNKNOWN. It uses months when under 1 year, and reads the date in IST.
  - `isFinished(c: Cycle, now: Date): boolean`, which is `c.cycle_year < istYear(now) || c.harvest_started_at !== null`.
  - `yearOnYear(cycles: Cycle[], now: Date): { unit: string | null; years: Array<{ year: number; value: number | null; unit: string | null; barred: boolean; soFar: boolean }>; latest: Cycle | null; previous: Cycle | null }`.
    - `years` are newest first.
    - `unit` is the latest finished cycle's `yield_unit` that has a yield.
    - `barred` is true when `value != null && unit === unit`.
    - `soFar` is true when the cycle is not finished.
    - `latest` and `previous` are the two most recent finished cycles.
  - `compareRows(latest: Cycle, previous: Cycle | null): Array<{ key: 'yield' | 'flowerDrop' | 'fruitDrop' | 'pests'; now: string; before: string; trend: 'better' | 'worse' | 'same' | null }>`.
    - A drop level of UNKNOWN is "—" with a null trend. The rank is NONE 0, LOW 1, MEDIUM 2, HIGH 3.
    - Yield is compared only when both values exist in the same unit.
    - Pests compare `pest_pressure_score`; fewer is better.
  - `groupByYear(entries: JournalEntry[]): Array<{ year: number; entries: JournalEntry[] }>`, using the IST year of `timestamp`, newest year first, preserving order inside a year.
  - `entryTags(e: JournalEntry): Array<{ key: string; values?: Record<string, string | number> }>`.
    - HARVEST gives `{key:'harvest', values:{amount:'120 kg', quality:'Good'}}`. It reads `quantity_value`/`quantity_unit`, or falls back to the legacy `quantity` string; quality is omitted when absent.
    - FLOWER_DROP and FRUIT_DROP with `severity` give `{key:'drop', values:{severity}}`.
    - Anything else gives `[]`.
  - `TIMELINE_FILTERS: ReadonlyArray<{ id: 'all' | 'care' | 'bloom' | 'harvest' | 'health' | 'notes'; types: readonly string[] }>`, using the spec §2.7 lists (`all` has `[]`).
  - `memoryFor(p: PlantDetail, now: Date): { kind: 'planted' | 'firstHarvest'; years: number } | null`. The spec §2.8 rules apply, planting wins, and years must be at least 1.
- [ ] **Step 1: Write the failing tests** (one `describe` per function), with these exact cases:
  - `plantAge`:
    - `('2015', 'YEAR', 2026-11-10)` gives `{unit:'years', count:11, year:2015}`;
    - `('2026-03-01', 'MONTH_YEAR', 2026-11-10)` gives `{unit:'months', count:8, year:2026}`;
    - `(null, 'UNKNOWN', …)` gives `null`.
  - `yearOnYear`:
    - cycles 2026 (soFar, no harvest), 2025 (40 kg), 2024 (3 crates), 2023 (30 kg) give `unit:'kg'`; 2024 has `barred:false`; 2026 has `soFar:true`; `latest`=2025 and `previous`=2024.
    - Review Focus #4.
  - `compareRows`:
    - flower drop LOW now against HIGH before gives `'better'`;
    - UNKNOWN gives `'—'` and `null`;
    - yield 40 kg against 30 kg gives `'better'`;
    - yield kg against crates gives a `null` trend;
    - pests 0 against 2 gives `'better'`.
  - `groupByYear`: `'2025-12-31T20:00:00Z'` is in year 2026 (Review Focus #5).
  - `entryTags`:
    - `{quantity_value:120, quantity_unit:'kg', quality:'good'}` gives amount `'120 kg'`;
    - the legacy `{quantity:'3 kg'}` gives amount `'3 kg'` (Review Focus #3);
    - FRUIT_DROP `{severity:'HIGH'}` gives drop.
  - `memoryFor`:

    - `first_harvest_at` 2023-11-20 on 2026-11-10 gives `{firstHarvest, 3}`;
    - the same year gives `null`.
